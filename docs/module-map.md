# Module map (full)

Dungeon removal (2026-11, steps A–E2) deleted the dungeon: its floors, tutorial and extras,
combat, the light and fog, the turn-based look, and in E2 the leftovers the ship never reaches
(stairs, keys, coins, papers, boxes, the desk, the chest, the glyph pass, the answer line). The old
PRs keep that code. Some long rows below still tell a file's history; its header comment is the
current word.

Rules and data (no page/DOM access):

| File | Job |
|---|---|
| `config.js` | Tunable constants and sample data. Never changes at runtime. |
| `state.js` | The one shared `state` object, plus `key(r, c)` and its reverse `parseKey(k)` (→ `{ row, col }`). Grouped by lifetime: `state.settings` (start screen / DEV panel), `state.run` (one run, including `state.run.ship`), `state.floor` (the ship as built), `state.battle` (the question being asked). |
| `grid.js` | `FOUR_STEPS` (the four ways, in the order every four-way search uses) and `stepsFrom(from, blocked, stopAt)`: walkable four-way steps to every tile reached (a Map), `stopAt` reached but not walked through; decor.js `makePlacer` uses it to keep every tile reachable. |
| `random.js` | `shuffle(list)` (a shuffled copy), shared by every rule that rolls. |
| `text.js` | All wording: `t(key, vars)` (with `{placeholders}`, `{@other.key}` references, `|upper` / `|plural`), and `applyStaticText()` for the `data-t` labels in index.html. |
| `plans.js` | `FLOOR_PLANS.ship`: the ship's plan, the same every run: rows of text (`S` the start) and room rectangles, their `name`s (`text.js` keys, `plan.ship.galley`, shown on first entry and on the minimap), each room's `furniture` (`[piece, row, col, width]`, pieces in `FURNITURE_PIECES`) and the `stations` (`[kind, row, col, role]`). `buildPlanLayout(plan)` returns the layout floor.js builds from. The dungeon's plans went in dungeon removal step D. |
| `decor.js` | Furnishing the ship: `placeFurniture(layout, placer)` puts each room's pieces down as props of `kind: 'furniture'` with `piece` and `part` ('single' / 'left' / 'mid' / 'right'), through `makePlacer(layout, size)` (`tryBlock`: a piece that would cut the floor in two is left out). Furniture blocks walking but not sight. Tested in `tests/furniture.test.mjs`. |
| `floor.js` | `buildShipFloor()`: the ship as data (its plan's layout and furniture, the stations, the safe room with automatic shutters, the windows), every tile lit and seen. The dungeon's floor builders went in dungeon removal step B. |
| `passage.js` | `whatBlocks(row, col)`: the single answer to "can I step here?": null, or `{ kind, thing }` with kind `wall` (also the grid's edge), `pillar`, `furniture` (a bump only says what it is, `furniture.<piece>` in text.js) or `prop` (a station or a shut shutter, which a bump examines). `solidProp(p)`: the one rule for what stops a step (an up shutter is open floor). |
| `sight.js` | What the player sees on the ship: `computeVisibility` (every open tile in `visibleSet` and `exploredSet`: the ship is lit everywhere), `canMakeOut` (within `REVEAL_DISTANCE` with a clear line), cover for a crouched player (`besideCover()`; walk.js says `coverTaken` once). |
| `look.js` | The light's angle: `state.floor.facing` is the body (8 ways; `nearestWay(angle)`), `state.floor.look` the light's own angle (radians on the grid, 0 = north). `lookAngle()` = that angle, or straight ahead. `aimLook(angle)` (a tap on the floor) sets `state.floor.lookWant`, and `swingLook(dtMs, still)` swings the light round to it at `ONE_STICK.turnRate`, the body facing the way nearest the light. `bodyAngle()`, `wrapAngle()`, `BODY_ANGLES`. |
| `modifiers.js` | The question modifiers' own rules: `maxWager()` (the Gambler's most), `blindReadMs(text)` (how long a question shows under Blind, shared by questionview.js and Verdict), `rollFlip()`. Which modifiers a question carries is minigames.js `modifiersFor`. The fight rolls went with combat (dungeon removal step C). |
| `minigames.js` | Minigames (minigames plan, `ideas/minigames-plan.md` outside the repo): a question sometimes runs as a small game instead. `minigamesFor(q)` (which fit it), `MINIGAME_MODIFIERS` (the modifiers each supports; `modifiersFor(id, offered)` = all of them or null, so an offer it can't carry stays a plain question), `rollMinigame(q, offered)` (`MINIGAME_CHANCE`, never the same twice in a row via `state.run.lastMinigame`; sets `state.battle.minigame`; DEV → Minigame `state.settings.minigame` 'roll' / 'off' / an id, `forcedQuestion()` swaps in a question a forced one fits), `endMinigame(result)` (`minigameScored`). A result is `{ right, tier, given }`, tier '1' / '2' / 'X' or null (miss); the ship's settle rules (stations.js, roles.js) count a tier as right or wrong. Close Enough (number answers): `closeEnoughDial(q)`, `closeEnoughTier(dial, at)` (`CLOSE_ENOUGH_*`). Higher / Lower (whole-number answers no finer than `HIGHER_LOWER_MAX_AT` round steps): `higherLowerBar(q)`, `higherLowerHint(bar, at)` ('hit' / 'higher' / 'lower'), `higherLowerTier(n)` (`HIGHER_LOWER_TIERS`: guess 1 / 2 / 3 = X / 2 / 1). Slow Spell (one-word answers of `SLOW_SPELL_MIN_LETTERS`–`_MAX_LETTERS` letters; no Timer): `slowSpellWord(q)` (chars, fill order, `stopAt` = all letters but one), `slowSpellMatches(word, typed)` (the typed answer, case and extra spaces ignored), `slowSpellTier(shown, total)` (at most `SLOW_SPELL_X_SHOWN` = X, at most half = 2, more = 1). Syllable Split (one-word names, `answerType` name, of at least `SYLLABLE_SPLIT_MIN_PIECES` pieces, with `SYLLABLE_SPLIT_DECOYS` decoy pieces from the set's other names of 2+ pieces): `splitSyllables(word)` (rough split on vowel groups, digraphs / starting pairs kept, cached), `syllableSplitPieces(q)` (a question's own `syllables` field, "Ne-bu-chad" or a list, wins when it spells the answer), `syllableSplitTray(q)`, `syllableSplitTier(wrong)` (`SYLLABLE_SPLIT_TIERS`: clean = 2, one wrong = 1, then a miss). Neither word game runs a question whose wording holds its answer ("Spell Bartimaeus."). Letter Pool runs a whole category the player picked (a reload's, a fight's choice), not one question: `rollMinigame(q, offered, group)` adds it to the same roll when the group has a label and more than `LETTER_POOL_FORM` short one-word answers; main.js `dressQuestion` then asks `letterPoolQuestion(group)`, a stand-in question (`letterPool` = `letterPoolSetup(group)`: `hidden` answers sharing letters, `tiles`, every spellable `words`; answer = the hidden ones), never a haunt (haunts.js). `letterPoolCheck(pool, word)` ('hidden' / 'valid' / 'unknown'), `letterPoolTier(pool, formed, hiddenFound)` (all hidden = X, `LETTER_POOL_FORM` = 2, `LETTER_POOL_WEAK` = 1). Code Break (one-word answers of `CODE_BREAK_MIN_CHARS`–`_MAX_CHARS` letters or digits, a hyphen dropped; not number answers, but ports): `codeChars(text)` (letters and digits in capitals), `codeBreakSetup(q)` (`code`, `digits` for a number pad), `codeBreakMarks(setup, typed)` ('hit' / 'near' / 'miss' per character, right places first, each character counted only as often as the code has it; null for the wrong length), `codeBreakTier(n)` (`CODE_BREAK_TIERS`: guess 1 / 2 / 3 = X / 2 / 1). Verdict (any question with an `answerType`, `VERDICT_MIN_DECOYS` other answers of it in the set, no image, not holding its answer; the set needs `VERDICT_BOSS_CLAIMS` such questions; `verdictIndex()` caches per `activeData`): `verdictClaimCount()` (`VERDICT_BOSS_CLAIMS` 5 against the boss only, else `VERDICT_CLAIMS` 3), `verdictSetup(q, count)` (claims `{ q, shown, truth }` in a random order, `q` among them; `VERDICT_FALSE_SHARE` show another answer of the same type), `verdictTier(wrong, count)` (`VERDICT_TIERS` 0 wrong = X, 1 = 1; boss `VERDICT_BOSS_TIERS` X / 2 / 1). A result may list `missed` questions: `endMinigame` records each (not the one showing, which the settle rule records) as a haunt. Crosswire (no Flip: one-word answers of `CROSSWIRE_MIN_LETTERS`–`_MAX_LETTERS` letters, not holding their answer, with a partner in the set; `crosswireWords()` caches per `activeData`): `crosswireSetup(q)` (`across` = q, `down` = a partner, `at` = where they cross: a shared letter, never either word's first), `crosswireTier(acrossRight, downRight, reveals)` (both: `CROSSWIRE_TIERS` by reveals X / 2 / 1; one word 1; neither a miss); no picture questions. Fog Reveal (picture questions only, an `image` field; Flip and Gambler only): `fogRevealTier(covered)` (`FOG_REVEAL_X_COVERED` 12+ tiles = X, `FOG_REVEAL_2_COVERED` 6+ = 2, fewer = 1). Sum Lock (no modifiers; a crew role's game, and in practice): the set needs two `sumLockQuestions()` (whole answers 1–`SUM_LOCK_MAX_ADDEND`, no port or picture); a stand-in Sum Lock question that rolls picks it first (not twice in a row); gunactions.js `sumLockQuestion()` asks, a stand-in (`sumLock` = `sumLockSetup()`: `first`, `second`, `a`, `b`, `total`; answer "47 (40 + 7)"), never a haunt itself; `sumLockMatches(lock, typed)` (digits only; none = no answer yet). Right pays `SUM_LOCK_TIER` X; wrong reports both questions as `missed`. |
| `moves.js` | What a walk finds (walk.js calls both): `enterTile(facing)` (a new tile: the shutters work, sight is worked out again, `stepped`, the safe room's `reachBroken`, and `roomEntered { name }` the first time in a room) and `bumpInto(block)` (`blocked`, or a station's events from stations.js `useStation`). ## How the game moves (full)

How a frame flows (One stick, the only way since dungeon removal step B, `ideas/one-stick-plan.md`
outside the repo): controls.js `walkFrame()` runs every animation frame. While `clockMayRun()`, the
round stick's push (dpad.js `initWalkStick`) or the held move keys go to walk.js `walkFree()`: the
light swings round (look.js `swingLook`), the free spot moves at its pace, a new tile runs moves.js
`enterTile()` and a stuck push `bumpInto()` → events → `settleMove(events)` (as a step:
`applyTurnOutcome(events)`, which draws them and ends the ship's run if it is over). Then
`worldFrame()` redraws the ship's HUD. The ask screen
pauses it all; CHARGE.SYS and COMMAND.SYS don't.

How a question flows: bumping a crew member → roles.js `useCrew` → `jobStarted` → controls.js
`settleMove` → gunactions.js `openJob`; a breaker tapped on CHARGE.SYS → `breakerAsked` → main.js
`turnChargerWire` → `openBreaker`; a role picked on COMMAND.SYS → `openLearning`; the last crew member
taught → `bossReady` → `openBoss`. Each shows the question on the ask screen (gunpanels.js
`showQuestionScreen`), and its answer (or a minigame's result) is settled by stations.js / roles.js →
events → `endAsk(settle)` → `applyTurnOutcome(events)`. Combat (the gun, the dial, reloads, the
Struggle, stick men, the battle screen) went in dungeon removal step C; the old PRs keep it.

The step in turns (`movePlayer()`, the d-pad, DEV One stick OFF) went in dungeon removal step E1,
and moves.js `stepPlayer()` in step E2 (its rules tests now go through `enterTile`).
